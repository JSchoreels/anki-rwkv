## What changes for the answer-time head

### Export (anki-rwkv, branch `sm83`)
- **Separate, optional file next to the model**: `time_head.f32.bin` (same `ARWKVWEIGHTS1` container, the head's 4 tensors `time_mlps.0.{hidden,out}.{weight,bias}` + a 1-value `time_head.format_version` = 1) and `time_head.json` (spec: inputs, bins, edges, explicit-feature definitions, validity rule). The main `weights.f32.bin` stays **byte-identical**: the fork's state-cache identity includes the model file's SHA-256, so a changed weights file would force every profile to rebuild its RWKV state; the grade outputs are unchanged by construction (same file, same code path). A model folder without `time_head.f32.bin` loads exactly as before (backward compatible); an old fork ignores the new file (forward compatible). An int8 copy `time_head.int8.bin` is exported for completeness (the fork computes with f32 weights).
- Package folder `artifacts/models/sm72e25-time/` (head files, spec, head-only checkpoint, NumPy reference for the head + the 26 explicit features, test vectors for users 4676 and 1745 with the time inputs and outputs per instant row, parity.json, manifest.json, manual section) + zip + release notes. Script: `scripts/sm83_time_package.py`.

### Runtime (fork, Rust)
- `rslib/src/rwkv/answer_time.rs` (dimension-free, compiled once): `AnswerTimeHistory` (the 26 causal features, exact rule of the Python reference: per-grade and all-grade running medians from exact duration counts, card's last 3 times, counts, last grade, user's previous time, EMA 0.1, review index) and the output summary (per-grade median seconds by `median_log_s`, P(under 3.9 s), grade-mixed with the instant head's button probabilities).
- `engine.rs`: optional `AnswerTimeHead` loaded from `time_head.f32.bin` beside the weights; `SrsModel::answer_time_inputs` = the query's residual after the encoder and after each of the 4 layer rounds (layer-normalised, no affine) + the instant head's 128-wide layer; `RwkvInference::predict_answer_times(requests, history_features)`; valid only for query inputs on a later day than the card's previous review (elapsed days >= 1). Legacy (big model) never has a head.
- Collection side: RPC `RwkvAnswerTimeHistoryFeatures` (one pass over the canonical RWKV history, the same visitor the warm-up uses) returning the history features for the requested cards.
- PyO3 bridge: `predict_answer_times`, `has_answer_time_head`.

### Where predictions are shown today and the surface for this release
- Card info (`rwkv_card_info_rows`, served by `mediasrv` card stats): "RWKV computed R", "RWKV : Answer Button Probability", source, next S90 rows, after-review rows. **New rows** (same place, only when the head is loaded and the review is on a later day): "RWKV : Answer time" = predicted median answer time per grade (Again / Hard / Good / Easy) and the grade-mixed median; "RWKV : Fast Good chance" = P(answer under 3.9 s | Good).
- The workload simulator / RWKV-FSRS comparison use fixed per-grade costs (`RwkvWorkloadReviewModel::grade_seconds`); replacing them with per-card predicted times changes simulation results and is **not** in this release (follow-up). **Scheduling behaviour is unchanged.**

### Tests
- Native parity vs the Python reference (PyTorch frozen-feature path of the decision, fp32 and int8 weights) on the published users: per-grade bin probabilities within 1e-5 (the existing vector tolerance), and the Rust explicit features equal to the Python ones on the users' revlogs (within 1e-6, f64 medians). Grade outputs: weights file unchanged, plus a test that loading the head changes no grade output bitwise; a model folder without the head file loads and reports no head.
- Python: formatting / gating tests in the existing style (remote CI).
