# Output-aware T24 on the 732 set (SM158): design

Written Tue 11-24 about 03:40, before any 732-set row of a weighted label was scored. Branch `sm158`, worktree `C:/Users/jonat/workspace/wt/sm158`, cut from `origin/sm157` (4b2a86b6, the result commit of output-aware low-rank truncation (SM157)). GPU scoring only, no training, no refit.

## Why a separate test

The CPU pointer output-aware low-rank truncation (SM157) failed its own pre-registered rule (NO GO, `../sm157/RESULT.md`), but on 8 users the receptance plus removal-key weighting (`rk`) cut the T24 cost of the binding instant head of both Big models: Big two-head (SM91s2) instant +0.034% plain against +0.002% with `rk`, Big Instant-Only (SM99) instant +0.023% against +0.004%. That hypothesis was generated by the pointer, so SM158 is its own confirmatory test on fresh, larger data (the 732 set), with the rules below fixed before any of its rows exist. It is not a re-reading of SM157: SM157's verdict stands.

## Question

At unchanged stored bytes, does T24 with output-aware truncation (`rk`) cost less than plain T24 against int8 rows on the 732 set, by at least 0.05% on a head of each Big model, without making any head of any model significantly worse, and does it meet the 11-23 budgets?

## Method (unchanged code)

- Codec: `scripts/state_lowrank.py` as committed in SM157 (92e1ace3 / f27a3e0f); no source change in this branch. Label suffix `wrk`: the rank-r truncation of `S M^(1/2)`, multiplied back by `M^(-1/2)`, right factors quantized in the weighted space; M = R + beta E[kd kd^T] (beta = tr R / tr E[kd kd^T]), normalised to mean eigenvalue 1, ridge 1e-3 I, rounded to float16. Details in `../sm157/design.md` "Method".
- M: the one fitted in SM157, `../sm157/sm157-stats.json` (sha256 d0394c73e44d442a276e6e86031cde939abb942319f3068598ac2d8cae7c54fe; 100 training users of the 8k split, id >= 5000, none in the 732, 2,225 or 1,500 pools or in any validation or test list). Not refit. `SM157_STATS` points to it in every scoring command, and its sha256 is checked in every weighted row.
- On the GPU the weighted labels run the torch step loop (the fused CUDA kernel is for plain labels only), so their speed is measured on the smoke ticket.

## Rules (pre-registered; `sm158_report.py`, its selftest passes)

Statistic: % = 100 x (sum of the label's benchmark LogLoss x size / the same for the reference - 1), review-weighted, paired user bootstrap 2,000 draws, seed 0, 95% CI, on the 722 rule users of the 732 set (`showtime_report.compare`, as every 732 read-out). Conditions for every comparison: every user's row finite (no non-finite row) and at least 715 common users.

1. Budgets (the user's 11-23 budgets), per model and label, CI upper bound per head:
   - Big: vs its own int8 (REF) <= +0.15%.
   - Small: TOTAL cost vs the matching Big model at int8 <= +0.5%; six-layer Tiny: <= +1.0%. Matching: two-head against Big two-head (SM91s2), Instant-Only against Big Instant-Only (SM99), the model's own heads.
2. Weighted against plain at the same bytes (paired, the same users): D(m, h) = % of T24RK against T24 on model m, head h.
3. **Go for adopting `rk` over plain T24** (all of):
   - (a) for each Big model (Big two-head (SM91s2) and Big Instant-Only (SM99)), at least one head with the CI upper bound of D below 0 AND D at most -0.05% (an improvement of at least 0.05%);
   - (b) no head of any of the six models significantly worse: the CI lower bound of D is not above 0;
   - (c) T24RK rows finite for every user and at least 715 users for every model.
   With a go, the format per size becomes T24RK where T24RK meets the budgets for both models of the size; elsewhere T24 stays. Without a go, T24 stays everywhere. The report also says whether plain T24 meets the budgets (from the same rows).
4. Q2RK is reported the same way (budgets; Q2RK against Q2; Q2RK against T24 and against T24RK), for information on bytes against cost; it decides nothing.
5. Extra codec cost per write: the CPU microbenchmark of SM157 (`../sm157/check-cpu-sm157.json`, one thread, rank 2: K = 16 +11%, K = 32 +48% as implemented, dense `S M^(1/2)`) and the GPU review evaluations per second of T24RK and Q2RK against SM148's T24 and Q2 rows (model time), per model.
6. Long-card checks (cards with 128+ answers) are not run in SM158; bucket read-outs from `--prior-buckets` of the 732 rows (including the 128+ bucket) are warnings only.

## ETA rule (fixed here)

From the GPU smoke rows: for each model m and weighted label L, slowdown(m, L) = speed of SM148's GPU smoke rows for the plain label of the same rank tiers (T24 for T24RK, Q2 for Q2RK; the same 3 users, the same torch step loop at the time) / speed of L in this smoke, speed = reviews / model seconds summed over the 3 users; the slowdown is floored at 1 (a weighted label is never assumed faster than its plain label of SM148). Estimated model seconds on the 732 set = SM148's 732 model seconds of that plain label for m x slowdown; wall time = 1.3 x model time (the worst wall-over-model ratio of SM148's passes), plus 15 minutes for retry passes. If the total for both labels is above 8 GPU hours, Q2RK is dropped and only T24RK is scored. The estimate, the decision and the per-size expected minutes are written to `gpu/eta.json` by `sm158_report.py eta` before the first scoring ticket.
