Predicting memory with RWKV

RWKV is a recurrent network: it reads your Anki reviews one at a time and keeps a small, fixed-size memory for every card, note, deck, preset and you. From that memory it predicts how likely you are to remember a card after any delay. This page shows how, step by step.

2. The memory: a small matrix that learns while it reads

Inside each stream, every head keeps a state matrix S. Each review writes a value at a key; a later read with that key gets the value back. This toy uses 4×4 instead of 32×32 and four slightly overlapping keys, one per card.

3. From memory to a forgetting curve

The output head does not predict a single number. It predicts a whole forgetting curve, built as a weighted mix of simpler curves. The models on this site build that mix in two different ways; switch between them. Hover the chart to read a probability.

 

Each basis curve is an exponential decay 0.9t / s with a fixed stability s; the model only chooses the weights. Drag the bars to set them (they are normalised to sum to 1), or try a preset. Mixing fast and slow curves gives a long tail that a single exponential cannot: a card can be partly forgotten within a day yet keep a stable core for months. The real heads use 128 (Alex) or 64 (Expertium iter36) basis curves from 0.1 s to about 100 years, and add a learned correction at the same number of time points.
Expertium’s current runs (RWKV_GRU_HEAD=3, modelled on srs-benchmark’s GRU) use only 3 curves, but predict each one’s weight, stability S and decay d for every review: R(t) = Σ wi·(1 + t/Si)−di. That is a power-law shape, like FSRS’s forgetting curve, so a single curve already has a long tail. There is no correction head, so predicted recall can only fall over time. Dashed lines are the three curves; the solid line is their mix.

Either way, a separate Instant head predicts the four grades for the review that is about to happen.

Putting it together

  • Inputs. Each review becomes 92 numbers: intervals, the grade, the answer time, today’s workload, calendar cycles and random ID tags. See the architecture page.
  • Streams. The encoded review passes through the card stream, then deck, note, preset and user streams. Each stream is a stack of RWKV-7 layers whose memory is shared only among reviews with the same ID.
  • Two questions per review. A query copy with the grade hidden predicts the grade (Instant), and is not allowed to write to memory. The real review then writes to memory and predicts recall at the next review’s delay (Curve).
  • Training. All of this runs in parallel on the GPU over thousands of users’ histories. The R01 campaign made that training several times faster without changing a single bit of the result.
