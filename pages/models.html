Two RWKV models, same inputs, very different budgets

Both models pass each review through the same five streams: card, deck, note, preset and user. Alex's default model is wide (128 channels, 4 heads of 32). Expertium's latest model, run 110, is narrow (64 channels, 4 heads of 16) and keeps about 9 KiB of memory per card.

Which versions. “Alex” is the default model from srs-benchmark (commit 3effecc). “Expertium” is his run 110, s64hsm10, from rwkv-anki-autoresearch at commit 1f2e6b0 (optimization/LEDGER.md, row 14d): the d=64 trunk, 3 learned power-law curves with no correction head, two extra sibling-rating inputs, and Muon on the 26 key/value scale matrices. His architecture file for it is not published, so the layer layout and the 333,178 parameter total are derived, not his figure: this repository's reconstruction of his d=64 trunk, which reproduces his published 332,922 parameters for the trunk it builds on, plus 2 inputs × 128. Not published, so not shown: dropout and exact input list. His LEDGER gives run 110 a curve (ahead) LogLoss of 0.297534 and an instant LogLoss of 0.264587 on his validation half, with the 10-epoch schedule. The older iter36 config (32 channels, 64 fixed curves plus a correction head), which this repository trained earlier, is shown separately in the output heads.

The 92 numbers each review becomes

One square per input number, in the order the model receives them. Alex’s model uses exactly this vector. Expertium’s run 110 reads his own rebuilt review-time layout instead (103 columns in his earlier d=64 runs, plus 2 sibling-rating inputs in run 110: 105 in total, derived), of which this published 92-number layout is the closest relative. Striped squares are blanked on the query copy of a review, the row that has to predict the grade without seeing it. Hover a square or a group.

From review to prediction

Data flows top to bottom. Each stream re-sorts the reviews by its own ID, so the card stream only sees one card's history while the user stream sees every review. Bars are drawn to scale: bar width is the hidden width, segments are heads, the thinner bar under each layer is its feed-forward (channel-mixer) width.

Inside one RWKV layer

How a single layer splits its parameters. 100 squares = the whole layer (so the two grids are not to the same scale; the totals are). The four mixing matrices grow with width squared, so narrowing from 128 to 64 channels shrinks them 4×. Expertium keeps a channel mixer in only four of its 13 layers, and the first layer of each stream has no value-residual LoRA.

  • R, K, V, O: receptance (what to read), key (where to write), value (what to write) and output projections of the time mixer.
  • Decay LoRA sets how fast each channel of the memory fades; in-context rate LoRA sets how strongly a new review overwrites what the memory already holds at that key.
  • Gate LoRA scales the output; value-residual LoRA mixes in the first layer's value so deep layers keep a direct path to the input.
  • Channel mixer is a small squared-ReLU feed-forward network, applied after each time mixer.

What has to be remembered

At inference time every card, deck, note, preset and user carries its own recurrent state. Each small grid is one head’s state matrix in one layer (32×32 for Alex, 16×16 for Expertium); per layer the model also keeps a token-shift vector as wide as the hidden layer for the time mixer, and another for each channel mixer that is still present. Sizes are fp32.

Expertium’s own head is the single three-tick rug: his three curves have their weight, stability and decay predicted for every review, so the ticks only show where the stabilities start (1 hour, about 4 days, 1 year; this initialisation is this repository’s reading of his head code). Expertium’s current head: a few learned power-law curves

Expertium’s runs since iteration 31, including run 110, set RWKV_GRU_HEAD=N (N = 3), modelled on the GRU model in srs-benchmark. Instead of weighting dozens of curves with fixed stabilities, three small linear layers on the curve head’s hidden output predict, for every review, the weight wi, stability Si and decay di of N curves. The Instant head is unchanged.

R(t) = Σi=1..N wi · (1 + t / Si)−di    Si, di > 0, weights sum to 1

This is a power-law shape like FSRS’s forgetting curve. The correction head is switched off (the same as RWKV_NO_AHEAD_RESIDUAL=1), so every curve, and their mix, can only fall over time. The parameter totals on this page for Expertium describe run 110 and are derived from this repository’s reconstruction of his d=64 trunk (expertium/variants.py, expertium/model/variant_model.py), not read from a log of his runs. Try both kinds of head in the curve explainer on the home page.

Going smaller still: status, 2026-10-15

A separate effort tests a much smaller student model (331,511 parameters, 436 KB as int8) distilled from the fork model. It uses the d=64 shape of Expertium’s run 110 (this repository’s w64, 4 heads of 16, 3 power-law curves) on the published 92 inputs, without run 110’s sibling-rating inputs, his PAVA thresholds, his rebuilt input layout or his Muon on the scale matrices. The best scale-up so far, scale-w64kd-dec, scores +5.3% curve and +6.0% instant LogLoss against the fork with int8 weights and int8 state, on 464 held-out users the student never trained on (the fork is rescored fresh). That beats the 32-channel baseline (+6.7% / +7.3%) but misses the good-candidate bar of +1.0% / +1.5% LogLoss and +15% RMSE(bins); calibration (RMSE(bins) about +85%) is the main weakness. The comparison leans slightly in the fork’s favour: students train on 128-review chunks but are scored on full histories. Pending: a calibration screen (three paired seeds) of cool-downs on 1,024-review chunks against 128-review chunks, expected around 17:00 to 17:30; no decision yet. A multi-epoch scale-up will use its first epoch as a cheap go/no-go check.
